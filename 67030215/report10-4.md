## 1. การวิเคราะห์สัดส่วนข้อมูลตามมาตรฐานสากล (Architectural Byte Breakdown)

ตารางวิเคราะห์ขนาดของเฟรมข้อมูลตามมาตรฐาน RFC สำหรับการส่งคำสั่งเปิดไฟ LED บน ESP32 จำนวน 1 ครั้ง

### ตารางบันทึกการคำนวณสัดส่วนประสิทธิภาพข้อมูล (Payload Efficiency)

| รายการประเมิน | HTTP REST (POST) | UDP Datagram (Raw) | CoAP (PUT - RFC 7252) |
| :--- | :---: | :---: | :---: |
| **ชั้นสื่อสาร L4 Transport** | TCP | UDP | UDP |
| **ขนาด L4 Header** | 20–32 ไบต์ | **8 ไบต์** | **8 ไบต์** |
| **ขนาด L7 Application Header** | ~180–250 ไบต์ | **0 ไบต์** | **4 ไบต์** (Binary Header) |
| **ขนาดข้อมูลจริง (Payload)** | 14 ไบต์ (`{"state":true}`) | 6 ไบต์ (`LED_ON`) | 1 ไบต์ (`1`) |
| **ขนาดข้อมูลรวม (L4 + L7 + Payload)** | ~214–296 ไบต์ | **14 ไบต์** | **13 ไบต์** |
| **สัดส่วน Payload ต่อข้อมูลรวม (%)** | **~4.7 % - 6.5 %** | **~42.8 %** | **~7.7 % - 25.0 %** |
| **ปริมาณข้อมูลเมื่อส่ง 10,000 ครั้ง** | ~2.5 - 3.0 Megabytes | ~140 Kilobytes | ~130 Kilobytes |

$$\text{Payload Efficiency Ratio} = \frac{\text{Payload Size (Bytes)}}{\text{Total Transmitted Bytes}} \times 100\%$$

> **วิเคราะห์เชิงวิศวกรรม**
> ในการส่งคำสั่งเดียวกัน การใช้ **CoAP** หรือ **UDP** ช่วยประหยัดปริมาณข้อมูลแบนด์วิดท์ได้มากกว่า HTTP ถึง **15–20 เท่า** จึงลดระยะเวลาการเปิดใช้งานภาคส่งวิทยุ (Radio Airtime) ช่วยประหยัดพลังงานแบตเตอรี่และค่าบริการ Data Package บนเครือข่ายเซลลูลาร์ได้อย่างมีนัยสำคัญ
