## คำถามท้ายการทดลอง

1. นำผลการรัน `curl -i` (โหมด verbose เพื่อดู HTTP Response Header) มาแปะในรายงาน พร้อมวิเคราะห์ว่า HTTP Header มีขนาดกี่ไบต์ และข้อมูล JSON มีขนาดกี่ไบต์
```

   HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 47

{"pot_raw":1845,"free_heap":215892,"led":false}
การวิเคราะห์ขนาดของข้อมูล:HTTP Header มีขนาด 71 ไบต์:HTTP/1.1 200 OK\r\n (17 ไบต์)Content-Type: application/json\r\n (32 ไบต์)Content-Length: 47\r\n (20 ไบต์)\r\n (บรรทัดว่างปิดท้าย Header คั่นระหว่าง Header กับ Body = 2 ไบต์)รวมขนาด HTTP Header: $17 + 32 + 20 + 2 =$ 71 ไบต์ข้อมูล JSON (Body) มีขนาด 47 ไบต์:สตริง {"pot_raw":1845,"free_heap":215892,"led":false} นับจำนวนอักขระรวมเครื่องหมายทั้งหมดได้ 47 ตัวอักษร
```

2. หากในเครือข่ายมีคอมพิวเตอร์ที่ไม่รองรับ mDNS หรือปิดกั้นพอร์ต UDP 5353 จะเกิดผลกระทบอย่างไร และแก้ไขได้อย่างไร?
 ```
  ผลกระทบ: อุปกรณ์จะไม่สามารถแปลงชื่อโดเมน esp32-node.local ไปเป็นหมายเลข IP ของ ESP32 ได้ ทำให้เรียกใช้งานเว็บเซิร์ฟเวอร์ผ่านชื่อดังกล่าวไม่สำเร็จ (พบข้อผิดพลาดประเภท Host not found)

วิธีแก้ไข:

เข้าใช้งานผ่านหมายเลข IP โดยตรง (เช่น [http://192.168.1.37/api/status](http://192.168.1.37/api/status))

เปิดกฎ Firewall ให้ยอมรับแพ็กเก็ต UDP พอร์ต 5353 หรือเปลี่ยนเครือข่ายเป็น Private Network

กำหนดคู่ IP และ Hostname ลงในไฟล์ hosts ของเครื่องคอมพิวเตอร์โดยตรง
```

3. เหตุใดจึงต้องเรียกคำสั่ง `cJSON_Delete(root)` และ `cJSON_free(resp)` เสมอหลังจากประมวลผลเสร็จสิ้น?
```
  เพื่อป้องกันปัญหา หน่วยความจำรั่วไหล (Memory Leak)
การสร้างโครงสร้าง JSON ด้วย cJSON_CreateObject() และการแปลงเป็นสตริงด้วย cJSON_PrintUnformatted() จะทำการจองพื้นที่บน Heap Memory แบบพลวัต
เนื่องจากภาษา C ไม่มีการคืนหน่วยความจำส่วน Heap อัตโนมัติ จึงจำเป็นต้องเรียก cJSON_Delete(root) เพื่อล้างข้อมูลโหนดทั้งหมด และเรียก cJSON_free(resp) เพื่อคืนหน่วยความจำของสตริงผลลัพธ์ หากไม่คืนพื้นที่ทุกครั้งที่มี Request วิ่งเข้ามา ค่า Free Heap จะลดลงเรื่อย ๆ จนกระทั่งหน่วยความจำหมดและตัวบอร์ดค้างหรือรีบูตตัวเองในที่สุด
```
